# Internationalization (i18n) Setup

LunchPad uses [next-intl](https://next-intl-docs.vercel.app/) for internationalization. Currently, only English is supported.

## Current Configuration

- **Library**: next-intl (app router)
- **Locale**: English only (`en`)
- **Locales prefix**: Disabled (no `/en/` in URLs)
- **Messages file**: `messages/en.json`

## How to Wrap Strings

All user-facing strings should be wrapped in the `t()` translation helper.

### Server Components

For async server components, use `getTranslations()` from `next-intl/server`:

```typescript
import { getTranslations } from "next-intl/server";

export default async function MyPage() {
  const t = getTranslations();
  
  return <h1>{t("page.title")}</h1>;
}
```

### Client Components

For client components, use `useTranslations()` from `next-intl`:

```typescript
"use client";

import { useTranslations } from "next-intl";

export function MyComponent() {
  const t = useTranslations();
  
  return <h1>{t("component.title")}</h1>;
}
```

## Message Structure

Messages are organized hierarchically in `messages/en.json`. Use dot notation to access nested keys:

```json
{
  "common": {
    "home": "Home",
    "menu": "Menu"
  },
  "page": {
    "title": "Welcome",
    "description": "Welcome to LunchPad"
  }
}
```

Access these with:
- `t("common.home")` → "Home"
- `t("page.title")` → "Welcome"

## Adding New Strings

1. **Add the string to `messages/en.json`**:
   ```json
   {
     "newSection": {
       "newKey": "New string value"
     }
   }
   ```

2. **Use the translation in your component**:
   ```typescript
   const t = getTranslations();
   return <p>{t("newSection.newKey")}</p>;
   ```

3. **For dynamic values**, use the rich text API:
   ```json
   {
     "greeting": "Hello, {name}!"
   }
   ```
   
   ```typescript
   {t.rich("greeting", { name: "Alice" })}
   ```

## Adding a New Locale

When adding a new locale (e.g., Spanish):

1. **Create a new messages file**: `messages/es.json` with all keys from `messages/en.json` translated
2. **Update `lib/i18n.ts`** to support the new locale:
   ```typescript
   const locale = "en"; // Change to support locale parameter
   ```
3. **Update `next.config.mjs`** if you want to enable locale-prefixed URLs (currently disabled)
4. **Update middleware** if needed for locale detection
5. **Test thoroughly** that all pages render in the new locale

## Locales with URL Prefix

Currently, locale is not shown in the URL (`localePrefix: "never"` in middleware). To enable `/en/...` URLs:

1. Update middleware:
   ```typescript
   localePrefix: "as-needed", // or "always"
   ```
2. Update next.config.mjs if needed
3. All existing links will automatically prefix with the locale

## Key Files

- `lib/i18n.ts` - i18n configuration
- `messages/en.json` - English translations
- `middleware.ts` - i18n middleware integration
- `next.config.mjs` - next-intl plugin configuration

## Testing Translations

Run `npm run dev` and verify all pages render with translated text. Each locale should have a complete set of keys.
